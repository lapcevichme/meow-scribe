# bench — стенд ML-пайплайна

Python-реализация того же пайплайна, что `SherpaPipeline` на Kotlin (логика 1:1), плюс тестовый набор и метрики.

```bash
python -m venv .venv && .venv/Scripts/pip install sherpa-onnx jiwer soundfile numpy pyannote.metrics huggingface_hub
bash ../scripts/fetch_models.sh   # боевой набор → android/app/src/main/assets/models/
bash fetch_models.sh candidates   # кандидаты для сравнения → .cache/models/
python make_dialogs.py --lang ru --n 8                      # синтетические диалоги из Common Voice
python make_dialogs.py --lang en --n 3 --turns 10 --min-clips 3
python run.py --data data/ru --name prod --set language=auto   # прогон + eval
python sweep_diar.py --data data/ru --emb campplus eres2net --thr 0.7 0.8

# многоголосые и плохой микрофон
python make_dialogs.py --lang ru --n 9 --spk 2 3 4 --turns 24 --min-clips 6 --no-phone --prefix ru_multi --out data/ru_multi --seed 123
python degrade.py --src data/ru_multi            # → ru_multi_{far,cheap,babble,quiet}
python make_ami.py                               # живые совещания AMI → data/en_ami, data/en_ami_far
python sweep_recluster.py --data data/ru_multi data/en_ami --min-spk 0 6 8
python export_android_tests.py                   # файлы для MultiSpeakerTest на устройстве
```

| Файл | Что делает |
| :--- | :--- |
| `make_dialogs.py` | Диалоги из клипов Common Voice: 2–3 спикера, быстрые смены реплик, перебивания с наложением до 0.7 с, последний файл «телефонный» (8 кГц, 300–3400 Гц, шум). Эталон в формате экспорта |
| `pipeline.py` | VAD → LID → диаризация → ASR → склейка, все параметры в `Config` |
| `run.py` | Прогон папки → JSON + `*.meta.json` (RTF, время стадий) → eval |
| `eval.py` | WER (`wer` без пунктуации, `wer_p` с пунктуацией), DER (collar 0.25 / 0), ошибка таймстемпов реплик |
| `sweep_diar.py` | Перебор эмбеддингов и порогов диаризации с кэшем слов ASR |
| `make_ami.py` | Живые совещания AMI (англ., 3–4 спикера, ручная разметка слов): окна по 4 мин из гарнитур (`en_ami`) и из одного микрофона на столе (`en_ami_far`) |
| `degrade.py` | Порча звука с тем же эталоном: `far` (комната, RT60 0.5–0.9 с, шум), `cheap` (перегруз, клиппинг, 200–4000 Гц, фон 50 Гц, MP3 24 кбит/с), `babble` (гул голосов, SNR 10 дБ), `quiet` (−30 дБ + шум АЦП + усиление) |
| `sweep_recluster.py` | Перебор второго прохода диаризации (склейка мелких спикеров) с кэшем слов и сегментов |
| `export_android_tests.py` | Копирует часть файлов в `androidTest/assets/multi/` для `MultiSpeakerTest` |

## Результаты (ноутбук, 4 потока CPU)

Набор: 8 русских диалогов (39–87 с, 1 «телефонный») и 3 английских.

**Боевая конфигурация, профиль ACCURATE:**

| | WER | WER с пунктуацией | DER | RTF |
| :--- | ---: | ---: | ---: | ---: |
| ru | 3.4% | 6.7% | 6.3% | 0.13 |
| en | 14.8% | 17.7% | 7.3% | 0.12 |

Профиль FAST (`win_shift=0.25`): ru DER 8.9%, RTF 0.086, WER тот же.

**ASR, ru** (диаризация одинаковая):

| Модель | WER | WER с пункт. | RTF |
| :--- | ---: | ---: | ---: |
| **GigaAM v3 RNNT punct** | **3.6%** | **7.0%** | 0.11 |
| GigaAM v3 CTC punct | 3.6% | 8.7% | 0.10 |
| Zipformer-ru int8 | 8.8% | 23.6% (нет пунктуации) | 0.11 |
| NeMo FastConformer multilingual int8 | 11.0% | 16.7% | 0.11 |
| Parakeet TDT 0.6B v3 | 15.0% | 17.4% | 0.14 |

**ASR, en:** Parakeet TDT 110M — WER 14.5%, RTF 0.105; Parakeet TDT 0.6B v3 — 23.0%, RTF 0.147.

**Эмбеддинги спикеров** (DER, collar 0.25, ru / en, лучший порог):

| Модель | ru | en |
| :--- | ---: | ---: |
| **3D-Speaker CAM++ zh_en advanced (26 МБ)** | **7.8–8.3%** | **7.6%** |
| 3D-Speaker ERes2NetV2 | 8.3% | 16.2% |
| 3D-Speaker ERes2Net base | 11.9% | 10.8% |
| WeSpeaker ResNet34 | 50% | 48% |

CAM++ почти не зависит от порога (0.7–0.85). У ERes2Net при пороге 0.5 (по умолчанию) DER 31%: он находит лишних спикеров.

Сегментация pyannote: int8-версия поднимает DER с 6.9% до 11.3%, поэтому в сборке fp32 (6 МБ).

**LLM** (резюме, llama.cpp CPU, ноутбук): Qwen3.5-0.8B Q4_K_M — 370 ток/с на промпте и 44 ток/с на генерации, формат держит, если начать ответ за модель с «Название:». Gemma-3-1B формат ломает. Qwen3.5-2B пишет лучше, но весит 1.2 ГБ и вдвое медленнее.

## Многоголосые записи и плохой микрофон

Боевая конфигурация, `language=auto`. ru_multi — 9 диалогов по 1–2 мин (по три на 2, 3 и 4 спикера, до 24 реплик, перебивания); испорченные варианты — те же файлы.

| Набор | WER | WER с пункт. | DER | Спикеров найдено/эталон |
| :--- | ---: | ---: | ---: | :--- |
| ru_multi (чисто) | 4.6% | 8.0% | 13.1% | 8 из 9 файлов точно |
| ru_multi_quiet (тихо, издалека) | 6.9% | 10.4% | 14.3% | |
| ru_multi_cheap (перегруженный микрофон) | 9.1% | 13.0% | 26.3% | недосчитывает: 2/4 |
| ru_multi_babble (гул голосов) | 12.9% | 16.7% | 18.0% | |
| ru_multi_far (телефон на столе в комнате) | 25.0% | 27.3% | 34.5% | |
| en_ami (живые совещания, гарнитуры) | 32.0% | 38.8% | 27.5% | 5–6/4 |
| en_ami_far (то же, микрофон на столе) | 44.6% | 49.7% | 35.8% | 6–7/4 |

AMI — разговорная речь с «um/uh», обрывами и наложениями в эталоне; 30%+ WER для маленьких моделей там нормально, важнее DER и число спикеров.

Что нашлось и исправлено (Python и Kotlin одинаково):
1. **VAD на сплошном шуме отдавал всю запись одним куском.** На гуле голосов Silero не видит пауз, `max_speech_duration` не срабатывает, ASR на 105-с куске выдаёт мусор (WER 80–87% на двух файлах). Теперь куски длиннее 20 с режутся по самому тихому 100-мс окну (`ChunkSplitter`). babble: WER с пункт. 34% → 17%, DER 35% → 18%.
2. **LID путал русский с английским на реверберации** (WER 100% на файле). Если whisper-tiny по первым 29 с говорит «en», ответ подтверждается голосованием по 5 VAD-чанкам из разных мест записи. Русские файлы не замедляются, английские (11 шт.) по-прежнему «en».
3. **Диаризация дробила людей на живой речи** (AMI: 9–12 спикеров вместо 4, ru 4 спикера → 5). Второй проход (`Reclusterer`): спикеры с речью < 6 с (но < 15% всей речи) отдаются самому похожему по эмбеддингу CAM++ всей его речи. DER: ru 6.8 → 6.3%, ru_multi 14.2 → 13.1%, babble 20.1 → 18.0%, AMI 28.6 → 27.5%, хуже нигде. Склейку по порогу косинуса тоже пробовал — сливает разных людей (ru DER 12–32%), не включена.
4. Порог кластеризации sherpa 0.8 перепроверен на многоголосых: 0.9+ везде хуже.
5. **Перебивания и поддакивания.** На подкасте реплики рвались посреди фразы, а «да-да» второго собеседника приклеивалось к чужой реплике. Проверяли на 9 окнах AMI по 4 мин (`en_ami_bc`, 162 поддакивания внутри чужой речи в эталоне) плюс cpWER (WER по спикерам с оптимальным сопоставлением) и точностью спикера по словам. Склейка после ASR теперь такая:
   - строгая реакция («Да.», «угу,», «да-да-да», «Yeah.»), которую накрывают сегменты двух спикеров, уходит спикеру с коротким сегментом (`assign_backchannels`). «ну», «вот», «так» не трогаем: в русском это служебные слова, их перенос рвал фразы;
   - предложения от 1.5 с сверяются по голосу: эмбеддинг CAM++ предложения против центроидов спикеров, переход к другому крупному спикеру (≥ 10% речи) при перевесе косинуса ≥ 0.1 (`relabel_sentences`). Диаризация на быстром диалоге склеивает реплики разных людей в один сегмент, а пунктуация ASR даёт границы. Стоит ~4% времени обработки;
   - поддакивание другого спикера внутри предложения становится отдельной репликой поверх основной, основная не рвётся (`extract_backchannels`);
   - сглаживание коротких кусков внутри предложения 2 с → 1 с: на AMI 2 с портило DER.

   | AMI, 9 окон | WER | DER | cpWER | Спикер слова верный |
   | :--- | ---: | ---: | ---: | ---: |
   | без сглаживания | 34.6% | 31.9% | 45.7% | 87.9% |
   | сглаживание 2 с | 34.6% | 32.8% | 45.9% | 87.6% |
   | **сейчас** | 34.6% | 32.2% | **44.6%** | **88.6%** |

   80% поддакиваний AMI ASR не распознаёт вовсе (Parakeet их выбрасывает), из распознанных правильному спикеру теперь достаются 6 из 32 против 2. Русской разметки живой речи нет: на 20 мин подкаста разрывов посреди фразы 37 → 13 (без сглаживания → сейчас), из оставшихся большинство — быстрый обмен репликами через тире и вынесенные поддакивания. **Надо перепроверить на ru и ru_multi.**

Не решено: дешёвый перегруженный микрофон и дальнее поле — диаризация недосчитывает спикеров (голоса после клиппинга/эха становятся похожи), WER в дальнем поле 25%.

**На устройстве** (`MultiSpeakerTest`, эмулятор x86_64 4 ГБ): цифры совпадают с Python, RTF 0.18–0.22 на ru, 0.11–0.12 на AMI, пиковый RSS ≤ 302 МБ.

## На устройстве (эмулятор x86_64, 4 ГБ RAM, 4 ядра)

ru_03 (72 с): результат совпадает с Python один в один (WER 4.8%, DER 4.7%).
FAST: RTF 0.35 (VAD 1.3 с, диаризация 8.9 с, ASR 14.8 с), пиковый RSS 276 МБ. Сводка LLM — ещё ~15 с после готового транскрипта.

## Ограничения

- Наложение голосов: каждое слово получает одного спикера. Слова в зоне перекрытия уходят тому, у кого больше пересечение по времени; исключение — строгие поддакивания, они уходят перебивающему и становятся отдельной репликой.
- Поддакивание прямо поверх чужой речи диаризация часто не видит вовсе (нет второго сегмента), тогда оно остаётся в чужой реплике.
- «Телефонные» записи: диаризация хуже (DER до 12–20%), короткие реплики вроде «Да!» иногда сливаются с соседними.
- Русская синтетика собрана из чтения Common Voice, это не живой разговор: открытого русского набора с разметкой спикеров нет. Живой разговор проверяем на английском AMI.
