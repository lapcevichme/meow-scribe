# Интеграция SherpaPipeline и LLM (для Михаила)

Код пайплайна готов и лежит в зоне oatis123: `data/pipeline/sherpa/`, `data/llm/`, `src/main/cpp/` (llama.cpp + JNI).
Чтобы его включить, нужны правки в твоих файлах. Они собраны в `docs/integration.patch` (41 строка, накатывается на `main` без конфликтов):

```bash
git apply docs/integration.patch
bash bench/fetch_models.sh     # веса в assets + sherpa-onnx AAR в android/app/libs/ (~1 ГБ)
```

Что делает патч:

| Файл | Изменение |
| :--- | :--- |
| `app/build.gradle.kts` | `ndkVersion = "29.0.14206865"`, `externalNativeBuild` → `src/main/cpp/CMakeLists.txt` (CMake 3.31.6), `implementation(files("libs/sherpa-onnx-2.0.1.aar"))` |
| `di/PipelineModule.kt` | `FakePipeline()` → `SherpaPipeline` (инжектится Hilt) |
| `SessionDao` / `SessionRepository(Impl)` | `setSummary(id, summary)` — запись в уже существующее поле `sessions.summary` |
| `ProcessingManager` | после `saveResult` и автоэкспорта, если `config.useLlm`: `LlmSummarizer.summarize()` → `setSummary()`, прогресс идёт как `Stage.LLM` |

Контракт `domain/pipeline` **не менялся**.

## Что нужно на машине сборки

- NDK 29.0.14206865 и CMake 3.31.6 (AGP скачает сам, если приняты лицензии SDK).
- Интернет при первой сборке: CMake скачивает llama.cpp (тег `b12176`) через FetchContent. В рантайме приложению сеть не нужна.
- Первая нативная сборка занимает несколько минут: llama.cpp собирается под `arm64-v8a` и `x86_64`.

## Что стоит поменять на твоей стороне (по замерам)

1. **Язык по умолчанию `auto` вместо `ru`.** Сейчас английский файл с настройками по умолчанию распознаётся русской моделью. В режиме `auto` язык определяет whisper-tiny по первым 29 с речи (≈0.5 с на ноутбуке); на стенде угадал 11 из 11 файлов.
2. **Профиль.** `FAST`: диаризация вдвое быстрее, DER 8.9% вместо 6.9%. `ACCURATE`: наоборот. WER одинаковый. Диаризация весит 25 баллов, RTF — 10, и RTF оценивается относительно других команд. Решай, какой профиль ставить по умолчанию.
3. **Стадия LLM в UI.** Сессия уже в статусе `DONE`, а `ProcessingManager` ещё ~15 с публикует прогресс `Stage.LLM`, пока считается сводка. Сводка приходит через Flow сессии, экран транскрипта её подхватит сам. Возможно, стоит показать «Готовим сводку…» прямо на экране транскрипта.

## Как устроено

```
PCM 16 кГц → Silero VAD (чанки ≤20 с)
          → [whisper-tiny LID, если language=auto]
          → диаризация: pyannote-seg-3.0 + CAM++ эмбеддинги, кластеризация порог 0.8
          → ASR по VAD-чанкам: GigaAM v3 RNNT (ru, с пунктуацией) / Parakeet TDT 110M (en)
          → слова с таймстемпами → спикер по максимальному перекрытию с сегментами
          → реплики: смена спикера / пауза > 3 с / конец предложения + пауза > 0.4 с
Done (транскрипт сохранён, экспортирован) → Qwen3.5-0.8B: название + 3–5 пунктов резюме
```

Каждая модель загружается в начале своей стадии и освобождается в конце, поэтому пиковый RSS на эмуляторе около 280 МБ.
Во время ASR после каждого чанка отправляется `PipelineEvent.Partial` с репликами, уже разбитыми по спикерам.
