# Архитектурная концепция и продуктовый план: «Нейро-стенографист» (Android On-Device)

Документ описывает архитектурный пайплайн локальной обработки аудио, дизайн-систему, ключевые UX-киллерфичи и практические рекомендации для хакатона по созданию Android-приложения для транскрибации и диаризации без использования облачных сервисов.

---

## 1. Архитектурный пайплайн обработки аудио

Классическая ошибка — прогонять ASR (Whisper) по всей дорожке целиком, а потом пытаться разметить спикеров. В зашумленных диалогах с перебиваниями это гарантирует сбитые таймстемпы и смешение реплик. 

Оптимальный пайплайн разделяет зоны ответственности: **VAD определяет границы**, **эмбеддер определяет человека**, а **Whisper только переводит чистый звук в буквы**.

### Пошаговая детализация этапов:

1. **Pre-processing (Подготовка аудио):**
   * Конвертация любого входящего формата в моно $16\text{ kHz}$ PCM Float/Int16.
   * Нормализация громкости (RMS/Gain) для выравнивания шепота и громких реплик.
   * Легкий шумодав (RNNoise / DeepFilterNet-lite), настроенный без агрессивного гейтинга, чтобы не срезать междометия («хм», «ага», мычание).

2. **VAD (Voice Activity Detection):**
   * Модель **Silero VAD** (размер ~2 МБ в ONNX).
   * Вырезает участки абсолютной тишины и фонового гула.
   * Формирует первичный список речевых тайм-интервалов с фиксированными границами `start_ms` и `end_ms`.

3. **Diarization (Диаризация спикеров):**
   * Для каждого речевого отрезка извлекается 192- или 256-мерный вектор акустических признаков голоса (эмбеддинг).
   * Алгоритм кластеризации (Agglomerative Hierarchical Clustering с косинусным расстоянием) группирует схожие векторы.
   * Каждому кластеру присваивается временный локальный идентификатор (`speaker_1`, `speaker_2`).

4. **ASR (Speech-to-Text):**
   * Модель: **Whisper** (`base` или `small` в квантовании `q5_1` / `q8_0`) через `whisper.cpp` или `sherpa-onnx`.
   * Потоковая подача: Whisper обрабатывает только изолированные куски от одного спикера.
   * Параметры запуска: `suppress_non_speech_tokens = false` — чтобы модель не цензурировала и не выбрасывала паразитные звуки, за которые борется жюри.

5. **Global Identity Resolution (Кросс-сессионные спикеры):**
   * Вычисление среднего центроида для каждого спикера сессии.
   * Поиск в локальной базе Room: если $\text{Cosine Similarity}(\vec{v}_{new}, \vec{v}_{db}) > 0.78$, спикер связывается с сохраненным профилем.

6. **Post-processing & LLM (Закрытие обязательного критерия):**
   * Локальная ультралегкая LLM (SmolLM-135M / Qwen2.5-0.5B через `llama.cpp` или `MediaPipe GenAI`).
   * Задачи: расстановка знаков препинания и валидация соответствия вывода строгому JSON-контракту регламента.

## 2. Дизайн-система: Material 3 + M3 Expressive

Приложение строится вокруг эталонного опыта **Google Pixel Recorder**, дополненного философией **M3 Expressive**: выразительные формы, контрастная типографика, адаптивные скругления и пружинящие микровзаимодействия.

### 2.1. Концепция стилизации спикеров
Для реплик диалога используется контрастное дифференцирование по контейнерам темы:
* **Спикер 1:** Фон `MaterialTheme.colorScheme.primaryContainer`, текст `onPrimaryContainer`. Форма бабла: `RoundedCornerShape(topStart = 24.dp, topEnd = 24.dp, bottomEnd = 24.dp, bottomStart = 6.dp)`.
* **Спикер 2:** Фон `MaterialTheme.colorScheme.tertiaryContainer`, текст `onTertiaryContainer`. Форма бабла: `RoundedCornerShape(topStart = 24.dp, topEnd = 24.dp, bottomStart = 24.dp, bottomEnd = 6.dp)`.
* **Спикер 3+:** `secondaryContainer` / `surfaceVariant`.

### 2.2. Ключевые компоненты M3 Expressive
1. **Dynamic Audio Waveform Dock (Плавающий плеер):**
   * Закрепленный снизу плавающий остров (`Floating Docked Bar`) с сильным скруглением (`shape = CircleShape` или `RoundedCornerShape(32.dp)`).
   * Содержит крупную pill-кнопку Play/Pause (`FilledTonalIconButton`), шкалу прогресса и счетчик времени реплики.
2. **Интерактивные реплики (Karaoke Cards):**
   * Каждая реплика — реактивный `Surface`.
   * При совпадении таймстемпа реплики с `currentPosition` плеера карточка плавно масштабируется (`scale = 1.02f` с помощью `animateFloatAsState` со Spring-спецификацией) и подсвечивается легким аудо-контуром (`border = BorderStroke(2.dp, colorScheme.primary)`).
3. **Чипы спикеров (Assist Chips):**
   * Внутри карточки выводится капсула (`FilterChip` / `InputChip`) с аватаром котика и именем спикера. Нажатие на чип открывает модальный диалог переименования («Запомнить профиль»).
4. **Haptic Feedback:**
   * Тактильный отклик (`LocalHapticFeedback.current`) при старте/паузе воспроизведения и при клике на таймстемп для перехода.

## 3. Продуктовые и UX-киллерфичи (Как забрать 15 баллов за UX и Защиту)

Большинство участников ограничатся кнопкой выбора файла и зависающим экраном. Продуманный UX выделит проект на тестировании.

### 3.1. Интерактивный плеер «Pixel Recorder» (Караоке-эффект)
* **Представление результата:** Расшифровка рендерится не простыней текста, а списком карточек-сообщений в стиле чата с указанием спикера и таймингов.
* **Синхронизация воспроизведения:** Во встроенном аудиоплеере при прослушивании записи текущая активная фраза подсвечивается в реальном времени.
* **Мгновенный переход:** Тап на любую реплику в списке автоматически перематывает плеер на точный `start_ms`. Это позволяет экспертам мгновенно перепроверить спорное распознавание.

### 3.2. Профили спикеров «на лету» (Speaker Enrollment)
* В интерфейсе рядом со `speaker_1` выводится кнопка редактирования имени.
* Пользователь может заменить `speaker_1` на человекопонятное имя (например, «Кот Ученый») и нажать «Запомнить голос».
* При обработке следующего файла приложение автоматически показывает бейдж: *«Распознан: Кот Ученый (уверенность 91%)»*.
* **Важно:** В экспортируемом JSON сохраняются обязательные ключи `speaker_1`, а кастомные имена отображаются в UI или в опциональном поле `speaker_name`.

### 3.3. Переключатель аппаратных профилей (Performance Profiles)
Выбор режима обработки в UI перед стартом транскрибации:
* **«Эко / Турбо» (фокус на скорость RTF):** Silero VAD + Whisper Base q5. Моментальная обработка, минимальный нагрев.
* **«Максимальная точность» (фокус на WER):** Двухпроходный фильтр DeepFilterNet + Whisper Small q8 + диаризация с меньшим шагом окна.
* **Техническая плашка на экране:** Отображение реального времени инференса, рассчитанного значения **RTF** ($T_{proc} / T_{audio}$) и пикового потребления RAM. Жюри сразу видит инженерную проработку.

### 3.4. Инлайн-коррекция и переназначение спикера
* Если на стыке двух говорящих диаризация ошиблась, пользователь может в один клик через контекстное меню реплики сменить автора (`speaker_1` $\leftrightarrow$ `speaker_2`) без повторного перезапуска нейросетей.
* Кнопка немедленного реэкспорта обновленного JSON.

### 3.5. Прозрачный статус инференса (No-Freeze UI)
* Вся тяжелая обработка вынесена в `Foreground Service` с корутинами (`Dispatchers.Default`).
* Детализированный прогресс-бар:
  * `[1/4] Шумоподавление и нормализация... (100%)`
  * `[2/4] Детекция пауз и спикеров... (65%)`
  * `[3/4] Распознавание речи... (Чанк 4/12)`
  * `[4/4] Формирование JSON-протокола...`

## 4. Советы по регламенту и обходу подводных камней

| Риск регламента | В чем опасность | Решение команды |
| :--- | :--- | :--- |
| **Раздутый APK и лимиты** | Нельзя встроить 3-5 ГБ весов в APK; GitHub запрещает большие файлы; лимиты Android PackageInstaller. | Не хранить модели в `assets/`. Сделать стартовый экран с загрузкой локального ZIP-архива моделей или выбором папки с файловой системы смартфона. Подготовить готовую инструкцию по размещению файлов для жюри. |
| **Ловушка с LLM** | В требованиях стоит «обязательно», но в таблице критериев за нее 0 прямых баллов. Трата времени на LLM убивает проект. | Использовать ультралегкую квантованную модель (до 0.5B) исключительно как постпроцессор JSON и пунктуации. Не пускать аудио в LLM. Сделать в UI тумблер включения/выключения. |
| **Запрет интернета** | Приложение снимут с конкурса при любых внешних запросах. | Полностью убрать `<uses-permission android:name="android.permission.INTERNET" />` из `AndroidManifest.xml`. Не использовать дефолтный системный `SpeechRecognizer` Google. |
| **Специфика датасета «Котики»** | Ожидаются невнятные звуки, мычание, перебивания, фоновые шумы. | Не использовать строгие промпты Whisper («говори литературно»). Отключить `suppress_non_speech_tokens`. Настроить VAD на мягкий порог срабатывания (threshold 0.35–0.4), чтобы не потерять тихие вздохи. |
| **Формат вывода JSON** | Автотесты жюри сравнивают вывод парсером. Ошибка в имени ключа = 0 баллов. | Жесткая валидация структуры перед экспортом по контракту: `transcript` $\to$ `speaker_id` (string), `start_ms` (int), `end_ms` (int), `text` (string). |

## 5. Рекомендуемый стек библиотек

* **Базовый фреймворк:** **`sherpa-onnx`** (от k2-fsa).
  * *Почему:* Единая C++ библиотека с официальным AAR/Kotlin-биндингом под Android. «Из коробки» содержит Silero VAD, поддержку моделей спикер-эмбеддингов (PyAnnote/3D-Speaker ONNX) и инференс Whisper/Zipformer через единый ONNX Runtime с поддержкой NNAPI. Избавляет от необходимости писать свой NDK-слой.
* **UI-слой:** Jetpack Compose (BOM) + Material 3 (версия 1.3+ с поддержкой Expressive-токенов).
* **Хранилище профилей:** Android Room (SQLite) для сохранения центроидов спикеров и истории сессий.
* **Аудио-движок:** AndroidX Media3 (ExoPlayer) для фонового воспроизведения и точного считывания позиции в миллисекундах (`currentPosition`).
