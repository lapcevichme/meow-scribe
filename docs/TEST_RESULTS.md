# Методика и результаты тестирования

## Как тестировали

Пайплайн меряли на Python-стенде [`bench/`](../bench/README.md). Это копия `SherpaPipeline` с той же логикой и теми же весами, в которой удобно перебирать модели и параметры. Каждое изменение сначала проверялось на стенде на всех наборах сразу. В Kotlin оно переносилось, только если не ухудшало ни один набор. На устройстве результат сверяли с Python инструментальным тестом `MultiSpeakerTest`: цифры совпадают.

### Наборы

| Набор | Что это | Файлов |
| :--- | :--- | ---: |
| `ru` | Диалоги из клипов Common Voice: 2–3 спикера, быстрые смены реплик, перебивания с наложением до 0.7 с, один «телефонный» файл (8 кГц, шум) | 8 |
| `ru_dev` | То же, отдельная выборка для подбора параметров | 8 |
| `ru_multi` | 2, 3 и 4 спикера, до 24 реплик, 1–2 мин | 9 |
| `ru_multi_quiet` / `cheap` / `babble` / `far` | Те же файлы, испорченные: тихо издалека; перегруженный дешёвый микрофон с MP3 24 кбит/с; гул голосов, SNR 10 дБ; комната с RT60 0.5–0.9 с | 9 × 4 |
| `en` | Английские диалоги из Common Voice | 3 |
| `en_ami` | Живые совещания AMI (3–4 спикера, ручная разметка слов), окна по 4 мин, гарнитуры | 9 |
| `en_ami_far` | То же, один микрофон на столе | 9 |

Плюс одна реальная запись: научно-популярный подкаст на 20 минут, без разметки. На ней проверяли длинные файлы, память, разрывы фраз и сводку.

### Метрики

| Метрика | Как считаем | Код |
| :--- | :--- | :--- |
| WER | `jiwer`: без пунктуации (`wer`) и с пунктуацией и регистром (`wer_p`). По ТЗ пунктуация входит в WER, поэтому главный — `wer_p` | `bench/eval.py` |
| DER | `pyannote.metrics`, collar 0.25 с (и 0 для контроля), по репликам из экспорта | `bench/eval.py` |
| cpWER | WER по спикерам с оптимальным сопоставлением: ловит слова, ушедшие не тому человеку | `bench/eval.py` |
| Таймстемпы | Средняя ошибка границ реплик против эталона, мс | `bench/eval.py` |
| RTF | Время обработки / длительность аудио, без учёта LLM-сводки | `PipelineStats.rtf` |

## Результаты: качество

Боевая конфигурация, профиль «Точный», язык «Авто».

| Набор | WER | WER с пунктуацией | DER | cpWER |
| :--- | ---: | ---: | ---: | ---: |
| ru | 3.4% | 6.7% | 9.5% | 12.0% |
| ru_dev | 4.7% | — | 10.8% | 13.8% |
| ru_multi | 4.6% | 8.0% | 5.6% | 6.5% |
| ru_multi_quiet | 6.9% | 10.4% | 11.4% | 21.7% |
| ru_multi_babble | 12.9% | 16.7% | 13.6% | 20.5% |
| ru_multi_cheap | 9.1% | 13.0% | 19.0% | 33.1% |
| ru_multi_far | 25.0% | 27.3% | 29.3% | 44.5% |
| en | 14.8% | 17.7% | 7.3%¹ | — |
| en_ami (9 окон) | 34.6% | — | 30.2% | 40.0% |

¹ По сегментам диаризации, замер до сверки предложений по голосу.

DER здесь считается по репликам целиком, как они попадут в экспорт, с collar 0.25 с. В нём учтены и ошибки границ, и ошибки распознавания. AMI — спонтанная речь с «um/uh», обрывами и наложениями в эталоне. 30%+ WER на нём нормально для моделей такого размера, на этом наборе важнее DER и число спикеров.

### Что дал каждый шаг

| Изменение | Эффект на стенде |
| :--- | :--- |
| GigaAM v3 RNNT punct вместо Zipformer-ru | WER с пунктуацией ru 23.6% → 7.0% |
| Сегментация pyannote fp32 вместо int8 | DER ru 11.3% → 6.9% |
| Нарезка длинных кусков VAD по тишине | babble: WER с пунктуацией 34% → 17%, DER 35% → 18% |
| Подтверждение языка голосованием | Перестал путать русский с английским на реверберации (WER 100% → норма на файле) |
| Склейка мелких спикеров | DER ru 6.8 → 6.3%, AMI 28.6 → 27.5%, хуже нигде |
| Поддакивания отдельными репликами | AMI cpWER 45.9% → 44.6%; на подкасте разрывов посреди фразы 37 → 13 |
| Спикер предложения по голосу (кластеризация с проверками) | DER ru_dev 12.0 → 10.8%, ru_multi 8.0 → 5.6%, babble 17.8 → 13.6%, AMI 32.2 → 30.2%; на AMI спикер слова верный в 92.7% (было 88.6%) |

Сравнение моделей ASR, эмбеддингов и LLM с цифрами — в [`bench/README.md`](../bench/README.md).

## Тесты в репозитории

**Юнит-тесты** (`./gradlew :app:testDebugUnitTest`): 43 теста, все проходят. Покрывают:
- склейку слов и реплик, поддакивания и сверку предложений (`WordMergerTest`);
- нарезку VAD (`ChunkSplitterTest`) и склейку спикеров (`ReclustererTest`);
- ресемплер, форматы экспорта JSON/TXT/SRT, разбор ответа LLM, математику голосов и поиск.

**Инструментальные тесты** на устройстве (`androidTest`):
- `ModelsSmokeTest` — нативные библиотеки грузятся на этой архитектуре; время загрузки, RTF и RSS каждой модели;
- `LlamaSmokeTest` — llama.cpp;
- `MultiSpeakerTest` — полный пайплайн на файлах стенда, сверка метрик с Python.

Запуск:

```bash
./scripts/fetch_models.sh
cd android && ./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -e class com.lapcevichme.meowscribe.ModelsSmokeTest \
  com.lapcevichme.meowscribe.test/androidx.test.runner.AndroidJUnitRunner
```

Сводные цифры в CSV лежат в [`artifacts/test-results/`](../artifacts/test-results/).
