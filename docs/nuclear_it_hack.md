## 1. Формулировка задания

Разработайте Android-приложение, которое **локально** преобразует аудиозаписи разговоров в текст, автоматически определяя говорящих и разделяя их реплики.

Приложение должно формировать структурированную расшифровку диалога с указанием участников и временных меток.

Результат должен быть доступен для:
* Просмотра непосредственно в приложении;
* Экспорта в файл.

> **Важно:** Все этапы обработки должны выполняться исключительно на Android-устройстве.

---

## 2. Обязательные требования

Команда должна разработать приложение, которое:
- Работает под управлением **Android OS**;
- Использует **локальную LLM**;
- Импортирует аудиозапись из памяти устройства;
- Преобразует речь в текст (ASR / STT);
- Автоматически определяет и разделяет говорящих (диаризация);
- Формирует временные метки для реплик;
- Отображает полученную расшифровку в интерфейсе;
- Экспортирует результат в файл.

## 5. Входные и выходные данные

### Входные данные
- Аудиофайл, импортированный пользователем из локального хранилища Android-устройства, **либо** записанный напрямую через интерфейс приложения.

### Выходные данные
Структурированная расшифровка в формате **JSON**, содержащая:
- Текст каждой реплики (`text`);
- Идентификатор говорящего (`speaker_id`);
- Время начала и окончания реплики в миллисекундах (`start_ms`, `end_ms`).

#### Спецификация JSON-схемы
* `transcript` (`array`) — массив объектов реплик.
  * `speaker_id` (`string`) — идентификатор спикера.
  * `start_ms` (`integer`) — время начала реплики (в миллисекундах).
  * `end_ms` (`integer`) — время окончания реплики (в миллисекундах).
  * `text` (`string`) — расшифрованный текст реплики.

#### Пример JSON-вывода
```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

## 6. Регламент проверки решений

Работоспособность приложения проверяется экспертами на заранее подготовленных тестовых аудиозаписях (*диалоги котиков*). Все команды оцениваются на едином наборе тестовых данных.

### Порядок тестирования экспертами:
1. Установка предоставленного APK-файла.
2. Импорт трёх тестовых записей.
3. Запуск транскрибации и диаризации.
4. Экспорт результатов обработки.
5. Сравнение полученных расшифровок с эталонами.
6. Расчёт метрик:
   - **WER (Word Error Rate)** — показатель точности распознавания текста;
   - **RTF (Real-Time Factor)** — скорость обработки относительно длины аудио.

## 7. Градация сложности решений

### Базовый уровень
- Работающий Android APK;
- Импорт аудиофайла;
- Использование локальной LLM;
- Распознавание речи;
- Автоматическая диаризация;
- Временные метки реплик;
- Отображение и экспорт результата.

### Средний уровень (дополнительные возможности)
- Предварительная обработка аудиосигнала;
- Фильтрация пауз и неречевых фрагментов (VAD);
- Устойчивое определение участников при частой смене реплик;
- Восстановление знаков препинания и капитализации;
- Отображение интерактивного прогресса обработки;
- Воспроизведение аудио с переходом (синхронизацией) к соответствующей реплике.

### Ultra Pro Max (продвинутый уровень)
- Эффективная обработка фонового шума и некачественных записей;
- Распознавание коротких реплик и перебиваний;
- Обработка наложения голосов (одновременная речь нескольких участников);
- Устойчивое распознавание при различиях в тембре и манере речи;
- Тонкая оптимизация потребления оперативной памяти (RAM);
- Аппаратное ускорение инференса (NPU / GPU / NNAPI / Qualcomm QNN);
- Возможность ручного редактирования и повторной обработки отдельных фрагментов.
